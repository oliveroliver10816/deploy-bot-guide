Deploy Bot

Send a file to a Telegram bot. Pick which site it belongs to. The bot commits it to the right repo and deploys the right Heroku app, then tells you when it is live.

📎 Send file→ Tap the site→ Tap the folder→ 🚀 Deploy→ ✅ Live

1For the VA — how to update a site

You only ever need the Telegram app. You never touch GitHub, Heroku, or a terminal.

  1. Send the file to the bot Tap the paperclip 📎, choose File, and pick the file from your phone or computer.

    Send it as “File”, not as a photo. If you send an image the normal way, Telegram squashes it and renames it to something like photo_2026.jpg. The bot will tell you off and ask you to send it again properly.

  2. Tap which site it is for The bot shows a button for each site. If there is only one site set up, it skips this step.
  3. Tap the folder it goes in You will see the folders inside that site. Tap a folder to open it, ⬆️ Up to go back, then ✅ Put it here when you are in the right place.

    The bot remembers where you put things last time for each site, so usually it opens in the right folder already and you can go straight to Put it here.

  4. Check the summary, then tap Deploy The bot shows you exactly what will happen — the file name, the site, the full path, whether it replaces a file that is already there or adds a new one, and which app will be updated. If it looks right, tap 🚀 Deploy.
  5. Wait for the green tick The message updates itself as it goes: Committing… → Building… → ✅ Live. A build usually takes one to three minutes. You do not need to keep the chat open.

If you made a mistake

Send /undo. The bot lists the last five changes; tap the one you want reversed. It puts the old version of the file back exactly as it was and redeploys. If the file was brand new, undo removes it.

If you see “Build failed” — the file was saved to the repo, but the app did not update, so the live site is still showing the old version. The bot prints the last lines of the error. Send /undo to put it back, and tell Bob.

2First-time setup — owner only

The Worker is already deployed and waiting. What is left is creating the bot and telling it about your accounts. Roughly ten minutes, once.

  1. Create the bot In Telegram, message @BotFather → /newbot → give it a name and a username. He replies with a token that looks like 8123456789:AAH….

    This must be a brand-new bot, not the existing Claude bridge bot. That one runs shell commands on the server as root — the VA must never be able to message it.

  2. Hand the token over Send it to Claude, or run it yourself on the server: 
    /root/workspace/deploy-bot/setup.sh 8123456789:AAH…
    That stores the token as an encrypted Worker secret and points Telegram at the Worker.
  3. Say /start to your new bot You are recognised as the owner automatically, because your Telegram ID is already baked in.
  4. Connect GitHub Send /connect → tap GitHub → paste a token. The bot deletes your message the moment it reads it, so the token is not left sitting in the chat.

    Make the token at github.com/settings/tokens → Fine-grained token → select the two repos → Repository permissions → Contents: Read and write. Nothing else is needed.

  5. Connect Heroku Send /connect → tap Heroku → paste an API key from dashboard.heroku.com/account (Applications → Authorizations → Create), or run heroku authorizations:create.
  6. Register the repos Send /addrepo. The bot lists every repo that token can push to — tap one. Repeat for the second.
  7. Link the apps Send /addapp. The bot lists your Heroku apps — tap one, then tap the repo that deploys to it. Repeat for the second.
  8. Add your VA Send /adduser, then their Telegram ID number. They can get it by messaging the bot once — it tells them their ID even though it refuses them. Then they send /start and they are in.

3Adding a new repo or a new Heroku app later

This is the part that keeps working forever. Nothing needs rebuilding and nobody needs to touch code.

What you are addingWhat to do
A new repo
on an account already connected		/addrepo → tap the account → tap the repo. Done.
A new Heroku app
on an account already connected		/addapp → tap the account → tap the app → tap the repo it deploys from. Done.
A whole new GitHub account/connect → GitHub → paste that account's token. Then /addrepo as above. Both accounts work side by side.
A whole new Heroku account/connect → Heroku → paste that account's key. Then /addapp as above.
Another person/adduser → their Telegram ID.
Removing a person/deluser → tap them.

One app per repo. Linking a second app to a repo that already has one moves the link rather than creating two — so a single file push can never fan out into two deploys by accident.

4How it actually works

Worth knowing when something looks wrong.

The file goes in with one API call. The bot does not clone anything. It reads the file's current version marker from GitHub, then writes the new bytes back with that marker attached. If somebody else changed the same file in the meantime, GitHub rejects it and the bot tells you to send it again — it will not silently overwrite their work.

The deploy does not rely on Heroku's GitHub integration. The bot downloads the repo as an archive, uploads it to Heroku itself, and starts a build from that. This is why it works on private repos, and why it works even though the apps were never connected to GitHub in the Heroku dashboard.

The build is watched separately. A timer checks in-flight builds every minute and edits the original chat message with the result, so the answer arrives even if you closed Telegram. Anything still building after 30 minutes is reported as stuck rather than left hanging.

Undo is exact, not approximate. Every deploy records a pointer to the previous contents of that file before overwriting it, so undo restores those precise bytes rather than guessing from history.

If an app already auto-deploys from GitHub, the bot warns you when you link it and tells you to switch that off in the Heroku dashboard. Otherwise every change builds twice, and the two builds race.
